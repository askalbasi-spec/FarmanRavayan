# تصمیم‌های فنی — فرمانروایان

## انتخاب پیشنهادی
- Flutter برای اپلیکیشن Android، صفحات، تنظیمات و رابط راست‌به‌چپ
- Flame برای صحنه دوبعدی نبرد، چرخه بازی و انیمیشن‌های سبک
- هسته قوانین بازی مستقل از رابط کاربری و قابل‌آزمون با unit test
- ذخیره محلی در MVP؛ انتخاب سرویس حساب کاربری و backend پس از تثبیت مدل بازی

## مرزبندی معماری
- domain: مدل کارت، بازیکن، انرژی، نوبت، قوانین و نتیجه نبرد
- game: صحنه Flame، نمایش میدان و انیمیشن‌ها
- features: صفحه شروع، کمپین، مجموعه کارت، تنظیمات
- data: ذخیره‌سازی محلی و در آینده ارتباط با سرور

## آنلاین
رقابت آنلاین جزو چشم‌انداز محصول است، اما در MVP پیاده‌سازی نمی‌شود. پیش از فعال‌سازی آنلاین باید سرور مرجع وضعیت بازی، اعتبارسنجی نوبت‌ها، مدیریت قطع اتصال و جلوگیری از تقلب طراحی و آزمایش شود.

## ساخت اندروید
پس از ایجاد اسکلت Flutter و بررسی نسخه‌های سازگار Flutter/Flame، گردش‌کار GitHub Actions برای اجرای تست‌ها و ساخت APK اضافه می‌شود. امضای انتشار نیازمند keystore و GitHub Secrets متعلق به مالک پروژه است؛ هیچ کلید یا رمزی در مخزن قرار نمی‌گیرد.
